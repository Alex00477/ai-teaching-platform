# MVP 范围与优先级

## 文档职责

本文档只回答“产品服务谁、先做什么、暂时不做什么、何时可以发布”。角色权限、状态和失败处理以 [业务规则](业务规则.md) 为准，技术实现以 [技术方案](技术方案.md) 为准，验收以 [验收清单](验收清单.md) 为准。

## 产品目标与角色

平台服务学生和教师，先让双方在同一系统完成作业提交、批改和反馈。

- 学生：查看所属班级的作业和讲义，保存并提交作业，查看已确认批改结果，对错题请求 AI 讲解。
- 教师：管理自己负责的班级，发布作业和讲义，查看提交，人工批改或发起 AI 辅助批改。
- 管理员：不纳入 MVP；平台审核、运营报表和跨组织管理另行定义。

## P0：最小教学闭环

P0 必须能够独立运行并验证以下闭环：

1. 学生/教师注册、登录、退出和密码恢复，并保持角色隔离。
2. 教师管理班级，学生加入唯一班级。
3. 教师发布选择题、填空题和简答题作业；学生保存草稿并提交整份作业。
4. 教师人工批改，或发起整份作业的异步 AI 批改并确认结果。
5. 学生查看已确认反馈，并对错题发起 AI 讲解。
6. 教师上传并发布讲义，学生查看自己班级和科目的已发布讲义。
7. 提供受权限控制的基础 Agent 入口；模型调用和密钥由服务端管理。

P0 不承诺通用 Agent 编排、任意 Skill 安装、任意 MCP 执行或管理员后台。

## P1：闭环稳定后的补齐

- 教师按姓名或用户名搜索学生，以及多班级聚合统计。
- 已发布讲义的知识库索引和权限范围内检索。
- Agent 对作业、班级统计和讲义的受控自然语言查询。
- AI 批改失败重试、任务历史、缓存和基于真实数据的压测。
- 学生/教师模型型号、提示词等设置页面（是否允许用户自带 Key 仍待确认）。

## P2：明确延期

- 通用 Skill 市场、任意第三方 MCP 安装/授权/执行。
- 管理员后台、教师审核、学校级多租户和跨组织报表。
- OCR、复杂题型、复杂格式转换和移动端原生应用。

## 发布门槛

- P0 主流程和 [验收清单](验收清单.md) 中的关键失败/越权场景可执行并通过。
- P1/P2 不成为 P0 的隐含依赖，P0 的业务规则均能在 [业务规则](业务规则.md) 中找到唯一来源。
- PH8、服务器、域名和密钥只作为部署前置条件记录，不把真实凭证写入仓库。
